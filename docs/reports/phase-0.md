## 1. 実装内容の要約

| 領域 | 実装 |

| シード再現性 | カウンタ方式の乱数（状態なし・順序に非依存）、自前の決定論的数学関数（sin/cos/atan/atan2/exp/log）、状態ハッシュ |
| パラメータ | 全 54 値が単位と根拠 ID を持つ。プリセット JSON・URL での上書きと範囲検証。根拠台帳は `BIOLOGY.md` と `ENGINEERING.md` |

| 描画 | three.js r186 の WebGPURenderer（WebGL2 へ自動切替）。InstancedMesh で描画し、スナップショット間を補間する。参照シーン（1 mm / 10 mm グリッド、10 mm スケールバー、座標軸） |
| 計測 | HUD（FPS、フレーム時間 p50/p95、メインスレッド CPU、GPU タイムスタンプ、シミュ ms/tick、実際の速度倍率）、`?bench=1` の個体数スイープ、Node でのシミュレーション単体ベンチ |
| 早送り（ご要望） | ×0.25 / ×1 / ×2 / ×4 / ×8 / ×16 / ×32 / ×64 / ×128 / MAX のボタン。キーは Space・`.`・`[`・`]`・`M` |
| 検証の道具 | アプリ内の「Determinism check」ボタン、`scripts/browser-run.ts`（実際の Chrome を CDP で操作し、スモーク・スクショ・ベンチを実行。追加ライブラリなし） |
| テスト | 12 ファイル、151 件。層の依存方向、決定論を壊す API の禁止、行動ルールのマジックナンバー禁止、根拠 ID の整合も自動で検査する |

### 性能曲線（RTX 5070 Ti、1600×900、MSAA 有効）

描画（[phase-0-webgpu.csv](bench/phase-0-webgpu.csv)、[phase-0-webgl2.csv](bench/phase-0-webgl2.csv)）:

| 個体数 | FPS | p95 フレーム | メイン CPU | GPU（WebGPU） | GPU（WebGL2） | シミュ ms/tick（ブラウザ） | 実時間比 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1,000 | 59.95 | 16.96 ms | 0.71 ms | 0.15 ms | 2.66 ms | 0.49 | ×1.00 |
| 10,000 | 59.95 | 16.96 ms | 1.13 ms | **0.64 ms** | 3.16 ms | 4.34 | ×1.00 |
| 50,000 | 59.95 | 17.02 ms | 2.51 ms | 3.48 ms | 4.08 ms | 14.16 | ×1.00 |
| 100,000 | 59.95 | 16.90 ms | 2.79 ms | 6.58 ms | 6.81 ms | 24.01 | **×0.68** |

シミュレーション単体（Node、[phase-0-sim-node.csv](bench/phase-0-sim-node.csv)）: 10,000 体で 2.40 ms/tick（最大 ×6.9 の早送りまで可能）、100,000 体で 25.2 ms/tick。

**ボトルネック**
1. **シミュレーションの CPU（Worker 1 本）** が先に限界に達する。1 体あたり約 240 ns/tick で、10 万体では実時間の 0.68 倍しか進まない。
   内訳を計測すると、正規乱数（Box–Muller）が 67 ns（うち dlog が 31 ns）、dsin/dcos が各 12 ns。
   ダミー歩行の数値なので、実際の行動ルールでは別途計測する。
2. 描画は 10 万体でも GPU 6.6 ms で、60 fps に余裕がある。WebGL2 は 1 フレームあたり約 2.5 ms の固定費があるが、10k 体の目標には十分。
3. ディスプレイが 60 Hz なので FPS は 60 で頭打ちになる。余裕の大きさは CPU / GPU の ms で判断している。

## 4. 「仮定」として置いたパラメータ

生物学的な仮定（ASM）は **ASM-SPC-001（データ不足時の補完順序）の 1 件のみ** です。
Phase 0 は生物学的な行動を持たないためです。生物学的な値は BIO-MOR-001（体長 5 mm）だけで、確度は「二次資料、原典ページ未確認」です。
そのほかの値はすべて技術的選択（ENG）で、[ENGINEERING.md](../ENGINEERING.md) に理由を書いています。主なものは次のとおりです。

- Δt = 1/60 s（ENG-SIM-001）
- ニア / ファー = 0.05 mm / 20 m（ENG-REN-002）
- ダミー歩行：20 mm/s、2 rad/√s、ストライド 2.5 mm（ENG-DBG-002〜004）。Phase 2 で削除する
- 仮ボディの形状比率（ENG-REN-008）。Phase 2 で形態データに置き換える

## 5. 次フェーズに進む前に判断していただきたいこと

1. **Phase 1 の地表の範囲と解像度**: 観察対象の地表を何 m 四方にするか。
   - 提案: 巣口を中心に 2 m × 2 m。高さ場は 0.25 mm 解像度で、カメラの近くだけ細かく描く。
   - 砂粒（0.1〜2 mm）・小石・落ち葉・草をどこまで実体（脚が接地できる形状）として持つかが、メモリと Phase 2 の IK に効きます。
2. **シミュレーションの多スレッド化の時期**: 1 万体 60 fps の目標そのものは現状の構成で満たせる見込みです（10k 体でシミュ 4.3 ms/tick、描画は別スレッド）。
   一方、早送りの上限は 1 万体で約 ×7 です。
   Worker の並列化（設計済みの 感知 → 判断 → 行動 → 相互作用 の段階分割）を、Phase 2 と同時に入れるか、Phase 3 で行動ルールの重さを見てから入れるか。
   - 推奨: Phase 3 の後。
3. **公開先**: 今後、成果をホスティングする予定はありますか。
   GitHub Pages などヘッダを付けられないホストでは、コピー転送方式（自動フォールバックで動作確認済み）になります。

## 補足（既知の制約）

- アプリ内ブラウザペインが非表示だと rAF が止まるため、描画の計測は `scripts/browser-run.ts` で、別に起動した Chrome（スロットリング無効化）で行いました。
- Windows の Chrome は `powerPreference` を無視するという警告を出します。ただし、このマシンの GPU は 1 枚（RTX 5070 Ti）なので影響はありません。
- WebGPU のアダプタ情報は、プライバシー保護のため `nvidia / blackwell` までしか公開されません。WebGL2 側では `GeForce RTX 5070 Ti` と確認できました。
